# Contributing to Lucy AIOS Public

Thank you for taking the time to examine Lucy.

At this stage, the most valuable contributions are **technical review, reproducible critique, documentation, test concepts, verifier ideas, and public contract proposals**.

The canonical Lucy AIOS implementation is not contained in this repository.

---

## Good contributions

Examples:

- identify an ambiguous architecture boundary
- describe a concrete governance bypass scenario
- propose a better verifier contract
- improve an architecture diagram
- add a reproducible test case to a public POC
- improve documentation clarity
- identify a claim that needs stronger evidence
- propose an interoperability contract
- compare the design to relevant published systems or research

---

## Please separate facts from proposals

Use language such as:

- **Observed:** ...
- **Reproduced:** ...
- **Proposed:** ...
- **Hypothesis:** ...
- **Not verified:** ...

Lucy intentionally distinguishes "exists" from "works" and "works" from "verified."

---

## Pull requests

Keep pull requests narrow.

A useful PR should explain:

1. What problem does this solve?
2. Which public contract or document changes?
3. What evidence supports the change?
4. Does the change alter a security or authority assumption?
5. How can another person verify it?

---

## Private-core contributions

Do not submit private Lucy source code, leaked code, credentials, proprietary third-party material, or implementation details that were not intentionally made public.

Access to a private repository does not grant permission to republish its contents.

---

## Conduct

Be rigorous without being hostile.

Attack assumptions, evidence, boundaries, and code — not people.
